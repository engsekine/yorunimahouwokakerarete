# Feature Specification: フォロワーリストのインポートと差分表示（個人アカウント対応）

**Feature Branch**: `003-follower-import-diff`

**Created**: 2026-07-17

**Status**: Draft

**Input**: User description: "Instagram のデータエクスポート（followers/following JSON）をアップロードして、フォロワー一覧のスナップショットを保存し、前回との差分（新規フォロー/フォロー解除した相手）を表示する"

> **007 による置き換え（2026-09-18）**: 比較対象の決め方・記録の保持ルール・アカウント名不一致時の扱いは [007-account-scoped-comparison](../007-account-scoped-comparison/spec.md) が優先する。具体的には、比較対象は「取り込み時に指定したアカウント ID が同じ前回の記録」、保持する記録はブラウザ全体で最大 2 件（最新 + 前回）、比較できるアカウントは 1 つ（別アカウントの記録があれば取り込みを拒否し「すべて削除して取り込む」を提供）。本書の US3（無制限履歴）・FR-006・FR-010・Assumptions の該当箇所は 007 に読み替える。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - エクスポートファイルを取り込む (Priority: P1)

Instagram の「あなたの情報をエクスポート」機能で取得したデータエクスポート（ZIP そのまま、または解凍した `connections/followers_and_following/` フォルダ内のフォロワー/フォロー中ファイル）を 本アプリにアップロードすると、フォロワー一覧・フォロー中一覧がその時点のスナップショットとして保存され、件数と取込日時が表示される。個人アカウント（プロアカウント以外）のユーザーでも利用できる。

**Why this priority**: 取り込みが成立しないと差分もなにも始まらない。個人アカウントのユーザーが 本アプリを使える最初の入口。

**Independent Test**: テスト用のエクスポートファイル（ZIP / JSON）をアップロードし、フォロワー件数・フォロー中件数・取込日時が表示され、スナップショットが保存されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** ログイン済みのユーザーがインポート画面を開いている, **When** エクスポート ZIP をそのままアップロードする, **Then** ブラウザ上で必要ファイル（フォロワー/フォロー中・本人情報）だけが取り出されて送信され、フォロワー一覧・フォロー中一覧が保存されて件数と取込日時が表示される（メディア込みの大きい ZIP でも送信サイズは小さい）
2. **Given** インポート画面を開いている, **When** 分割されたフォロワーファイル（followers_1 / followers_2 …）を複数まとめてアップロードする, **Then** 全ファイルが統合されて 1 回の取り込みとして保存される
3. **Given** フォロワー一覧を含まない無関係なファイルをアップロードした, **When** 取り込みを実行する, **Then** 取り込みは行われず「followers_and_following フォルダ内のファイルをアップロードする」旨の日本語案内が表示される
4. **Given** アップロード中・解析中, **When** 処理に時間がかかっている, **Then** 進行中であることが分かる表示が出て、完了または失敗が通知される

---

### User Story 2 - 前回との差分を見る (Priority: P1)

2 回目以降の取り込みを行うと、前回のスナップショットと比較して「新しくフォローしてくれた相手」と「フォローを外した相手」の一覧が、それぞれの件数とともに表示される。各相手はユーザーネームで表示され、Instagram のプロフィールへ移動できる。

**Why this priority**: 「誰が増えて誰が外したか」が本機能の中核価値。公式手段では得られない情報を規約準拠で提供する。

**Independent Test**: 内容の異なる 2 つのテスト用エクスポートを順に取り込み、既知の差分（追加 2 名・削除 1 名など）が正しく表示されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 過去に 1 回以上取り込み済みのユーザー, **When** 新しいエクスポートを取り込む, **Then** 前回スナップショットとの差分として「新規フォロワー」「フォロー解除した相手」の件数と一覧が表示される
2. **Given** 差分一覧が表示されている, **When** 一覧内の相手を選択する, **Then** その相手の Instagram プロフィール（外部）を開ける
3. **Given** 前回と同一内容のエクスポートを取り込んだ, **When** 差分を表示する, **Then** 「変化なし（差分 0 件）」であることが明示される
4. **Given** 初回取り込みのみのユーザー, **When** 差分画面を見る, **Then** 「比較対象がまだない」旨と次回取り込みの案内が表示される

---

### User Story 3 - 取り込み履歴と過去の差分を見る (Priority: P2)

> 007 により、履歴に残る記録は最大 2 件（最新 + 前回）となり、各行にアカウント ID が表示される。以下の「時系列で確認」は 2 件の範囲に限られる。

ユーザーは過去の取り込みの一覧（取込日時・アカウント ID・フォロワー件数）を時系列で確認でき、任意の取り込みを選ぶとその時点の直前取り込み（同じアカウント ID）との差分を再表示できる。不要な取り込みは削除できる。

**Why this priority**: 差分は蓄積されてこそ「推移」になる。ただし直近の差分（US2）が成立していれば初期価値は出る。

**Independent Test**: 3 回取り込んだ状態で履歴一覧に 3 件表示され、2 番目を選ぶと 1→2 回目間の差分が表示されること、削除で履歴から消えることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 複数回取り込み済みのユーザー, **When** 履歴一覧を開く, **Then** 取込日時とフォロワー件数が新しい順に表示される
2. **Given** 履歴一覧, **When** 過去の取り込みを選択する, **Then** その取り込みと直前の取り込みの間の差分が表示される
3. **Given** 履歴一覧, **When** 取り込みを削除（確認ステップ付き）する, **Then** その取り込みが履歴から消え、前後の取り込み間で差分が再計算される

---

### User Story 4 - フォロー関係の分析 (Priority: P3)

最新の取り込みに含まれるフォロワー一覧とフォロー中一覧を突き合わせ、「自分がフォローしているのにフォローバックされていない相手」「フォローされているのに自分がフォローバックしていない相手」を一覧表示する。

**Why this priority**: エクスポートに含まれる情報だけで実現できる付加価値。差分（US2）より優先度は下がる。

**Independent Test**: フォロワーとフォロー中が部分的に重なるテストデータを取り込み、非相互の 2 一覧が正しく表示されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** フォロワー・フォロー中の両方を含む取り込みがある, **When** 分析画面を開く, **Then** 「フォローバックされていない相手」「フォローバックしていない相手」の件数と一覧が表示される
2. **Given** フォロー中一覧が取り込まれていない（フォロワーのみの取り込み）, **When** 分析画面を開く, **Then** フォロー中一覧を含むエクスポートが必要である旨が案内される

---

### Edge Cases

- 分割されたフォロワーファイル（1 万人超のアカウントでは複数ファイルに分かれる）を漏れなく統合して取り込める
- 別アカウントのエクスポート（過去の取り込みとアカウント名が一致しない）を取り込もうとした場合、上書きせずに警告し、ユーザーが明示的に確認した場合のみ続行する
- フォロワーがユーザーネームを変更した場合、エクスポートには安定した識別子が含まれないため「解除 + 新規」として二重計上され得る。この制約を差分画面上で注記する
- 極端に大きいファイル（上限超過）は取り込みを拒否し、上限を明示する
- 取り込み処理の途中で失敗した場合、中途半端なスナップショットが残らない（全件成功か、取り込みなしか）
- アップロードされたファイルにフォロワー/フォロー中一覧が含まれない（言語設定によるパス差異・Meta 側の構成変更・対象外ファイルの選択）場合、失敗理由と対象ファイルのアップロード手順を案内する
- フォロワー 0 件のエクスポートも正常に取り込める（全解除として差分計算される）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはログイン済みユーザーに対し、Instagram データエクスポートのアップロードによるフォロワー一覧・フォロー中一覧の取り込みを提供しなければならない
- **FR-002**: アップロードは「エクスポート ZIP そのまま」と「followers_and_following フォルダ内のフォロワー/フォロー中ファイル（HTML / JSON・複数可）」の両方を受け付け、分割ファイルを統合して 1 回の取り込みとして扱わなければならない。ZIP はブラウザ上で必要ファイルだけを抽出してから送信し、ZIP 全体はサーバーへ送らない
- **FR-003**: 取り込みごとに、フォロワー一覧・フォロー中一覧（各相手のユーザーネームとプロフィール URL、エクスポートに含まれるフォロー日時）をスナップショットとして取込日時付きで保存しなければならない
- **FR-004**: 取り込み完了時に、直前の取り込みとの差分（新規フォロワー・フォロー解除した相手）を件数と一覧で表示しなければならない。差分 0 件の場合はその旨を明示する
- **FR-005**: 差分・一覧の各相手から Instagram プロフィール（外部）へ移動できなければならない
- **FR-006**: 取り込み履歴（取込日時・アカウント ID・フォロワー件数）を時系列で一覧表示し、過去の取り込みを選択して当時の差分を再表示できなければならない（保持件数は 007 FR-004 により最大 2 件）
- **FR-007**: 取り込みの削除を確認ステップ付きで提供し、削除後は前後の取り込み間で差分が整合しなければならない。加えて、保存されている取り込みデータ（履歴・フォロワー一覧）を一括で削除する操作をホームに確認ステップ付きで提供し、削除後は取り込みが無い状態に戻らなければならない
- **FR-008**: 形式不正・想定ファイル欠落・サイズ超過の場合は取り込みを行わず、日本語の失敗理由と「対象ファイル（followers_and_following フォルダ内）のアップロード手順」を案内しなければならない（生のエラー情報は表示しない）
- **FR-009**: 取り込み処理は原子的でなければならない（途中失敗時に中途半端なスナップショットを残さない）
- **FR-010**: 廃止 → 007 FR-007 / FR-007a / FR-008 に置き換え（別アカウントの記録があれば取り込みを拒否し「すべて削除して取り込む」を提供する。エクスポート内の本人名と入力値の相違は警告 + 確認で続行）
- **FR-011**: 取り込んだデータ（スナップショット・差分）は本人のみが参照・削除でき、他のユーザーからは一切アクセスできないようにしなければならない
- **FR-012**: 最新の取り込みからフォロー関係の分析（フォローバックされていない相手・フォローバックしていない相手）を表示できなければならない（フォロー中一覧がある場合のみ）
- **FR-013**: アップロード・差分表示・履歴・削除の各 UI はキーボードのみで完結でき、処理状態の変化が支援技術に通知される（WCAG 2.1 AA 準拠）ようにしなければならない

### Key Entities

- **フォロワーインポート（取り込み）**: 1 回のアップロードに対応する記録。所有ユーザー・対象アカウント名・取込日時・フォロワー件数・フォロー中件数を持つ
- **フォロワーリストエントリ**: 取り込みに含まれる相手 1 人分の記録。種別（フォロワー / フォロー中）・ユーザーネーム・プロフィール URL・エクスポート上のフォロー日時を持つ。ユーザーネームが相手の識別子となる（安定 ID は提供されない制約）
- **差分結果**: 隣接する 2 つの取り込みの比較から導出される「新規フォロワー」「フォロー解除した相手」の集合。保存せず取り込みスナップショットから都度計算できる導出データとして扱う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがエクスポート ZIP をそのままアップロードしてから、件数表示（取り込み完了）まで 1 分以内に到達できる
- **SC-002**: 既知の差分を持つ 2 つのテストエクスポートで、新規・解除の判定が 100% 一致する（誤検知・見逃し 0 件。ユーザーネーム変更による制約は注記の上で除く）
- **SC-003**: フォロワー 1 万件規模の取り込みでも、アップロード完了から差分表示まで 10 秒以内に完了する
- **SC-004**: 形式不正・構成違いのファイルに対して、100% 日本語の失敗理由と対象ファイルのアップロード手順が提示される（生のエラー露出 0 件）
- **SC-005**: 他ユーザーの取り込みデータへのアクセスが 0 件である（本人以外の参照経路が存在しない）
- **SC-006**: インポート関連の全画面が自動アクセシビリティ検査（WCAG 2.1 AA 相当）で違反 0 件である

## Assumptions

- 対象は Instagram の公式データエクスポート（アカウントセンター →「あなたの情報をエクスポート」）で取得した `connections/followers_and_following/` フォルダ内のファイルとする。**HTML / JSON の両形式**に対応する（HTML はフォロー日時を持たないため followedAt は null になる）。エクスポートの取得操作自体はユーザーが Instagram 上で行う
- エクスポートには相手の**安定した数値 ID が含まれない**ため、相手の同定はユーザーネーム基準とする。相手のユーザーネーム変更は「解除 + 新規」として現れる制約を明示する
- 差分は**同じアカウント ID の隣接する取り込み同士**の比較とする（任意の 2 時点の比較は将来拡張。007 FR-002）
- 1 ユーザーが管理できるインポート系列は自分の 1 アカウント分とする（007 FR-007 の別アカウント拒否がこの前提の保護。複数アカウント管理は将来拡張）
- サーバーへ送信されるファイルの上限は 10MB とし、上限は画面に明示する（ZIP はブラウザ上で必要ファイルのみ抽出してから送信するため、ZIP 自体のサイズは対象外。フォロワー/フォロー中の JSON・HTML は 10MB に十分収まる）
- サーバー側で ZIP を受け取った場合の展開後サイズは対象ファイル合計 100MB（`MAX_UNCOMPRESSED_BYTES`）を上限とし、超過は `zip_too_large` として拒否する。対象外ファイル（メディア等）はサーバー側でも展開しない（ZIP 爆弾によるメモリ枯渇対策）
- Instagram API との連携（アカウント接続・フォロワー数の自動取得）は行わない。本アプリのデータの入口はエクスポートの取り込みのみとする
- 取り込んだフォロワー一覧は第三者の個人情報（公開プロフィール情報）を含むため、本人のみ閲覧・エクスポート機能なし・削除可能とする
- 対象ユーザーは日本語話者とし、画面文言・エラーメッセージは日本語で提供する
