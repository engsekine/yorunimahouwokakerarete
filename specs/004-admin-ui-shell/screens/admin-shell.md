# 画面仕様: 管理画面シェル・ダッシュボード・各ページ — 004-admin-ui-shell

## 共通シェル（`(authenticated)` 全ページ）

```
┌───────────────────────────────────────────────┐
│ AdminTopBar: [≡] yorunimahouwokakerarete [🌗テーマ] user@… [ログアウト] │  ← <header>
├───────────┬───────────────────────────────────┤
│ Sidebar   │  main（各ページの children）           │
│ ▸ホーム      │   PageHeader（見出し + アクション）      │
│ ▸インポート   │   Card / DataTable / Notice …        │
│ (aria-     │                                     │
│  current)  │                                     │
└───────────┴───────────────────────────────────┘
```

| 要素 | 種別 | 備考 |
|---|---|---|
| 上部管理バー | `<header>` | サイドバートグル（≡）・サイト名・ThemeToggle・user email・LogoutButton |
| サイドバー | `<nav aria-label="管理メニュー">` | NAV_ITEMS・現在項目に `aria-current="page"`・折りたたみトグル |
| メイン | `<main>` | ページ children。ページ側で PageHeader を先頭に置く |

- デスクトップ: サイドバー常設（折りたたみで幅可変・Cookie 保持）
- モバイル: サイドバー非表示 → ≡ で Sheet として開く（選択で自動クローズ）。Sheet のタイトルはサイト名のみで、メニュー（先頭「ホーム」）の上に置く。右上の閉じるボタンと重ならないよう右に余白を取り、長いサイト名は折り返す

## ホーム（/・ダッシュボード）

トップ `/` がそのままホーム（WordPress のダッシュボード相当）。サイドバーのメニュー「ホーム」（exact 一致）に対応し、`PageHeader`（タイトル「ホーム」）→ データの取り扱いの注意 `Notice(info)`（見出し「データの取り扱いについて」+ 箇条書き: ブラウザ内 localStorage のみに保存しサーバーへ送信・保存しない / 運営側による利用者データの収集・解析・トラッキングは行わず取り込んだ内容も見られない / 公共・職場・学校などの共用パソコンや共有ブラウザでは取り込みを行わない（データは自動では消えず「取り込んだデータをすべて削除」で手動削除するまで残る） / 別端末に引き継がれない / サイトデータ消去で失われる / 元のエクスポートファイルを手元に残す）→ ウィジェットカード → `Card`「取り込んだデータの削除」（説明文 + `DeleteAllImportsButton`）→ `Card`「フォロワー数がわかる仕組み」（箇条書き 4 点: Instagram へのログイン・API 接続はせず元データは利用者自身のエクスポート / ZIP 内の followers_1.json・following.json をブラウザ内で読み取り一覧を保存し、その人数を数えている / 同じアカウント ID の前回一覧とユーザーネーム単位で照合して増えた相手・外した相手・増減を出す / 数字はエクスポート作成時点のもので最新化には再エクスポートが必要）の順に並べる。

### 取り込んだデータの削除（ホーム末尾の Card）

- `DeleteAllImportsButton`（003 の全削除ボタン・destructive）。取り込みが 0 件なら無効。一覧の取得に失敗している場合は破損データの掃除に使えるよう有効のまま
- 押下で `ConfirmDialog`（タイトル「取り込んだデータをすべて削除しますか？」・本文に取り込み履歴の件数・実行ボタン「削除する」）
- 成功: `role="status"` で「取り込んだデータを削除しました。」を表示し、取り込み系クエリを無効化してウィジェットが「取り込みなし」に戻る。失敗: `role="alert"` で日本語の案内

| ウィジェット | 内容 | 未設定時 |
|---|---|---|
| インポートサマリ | 最新取り込みの対象アカウント（`@ユーザー ID`）・フォロワー件数・取り込み日時（003 `listImports`） | 「取り込みなし」+ インポート導線 |

- 各ウィジェットは `Card` で構成し、対象機能ページへのリンク/ボタンを持つ（FR-005）
- 取得が失敗してもシェルは壊れない（FR-006）。失敗ウィジェットは Notice(info) で「取得できませんでした」
- 現時点のウィジェットはインポートサマリの 1 枚（Instagram 連携の削除に伴い連携サマリは廃止）

## インポートページ（/imports・/imports/[id]）

- `/imports`: `PageHeader`（タイトル「フォロワーインポート」+ アクション不要）→ アップロード `Card`（ImportUploadForm）→ 履歴 `DataTable`（取込日時・件数・行内に詳細リンク + 削除）
- `/imports/[id]`: `PageHeader`（タイトル「取り込み結果」）→ 差分 `Card`（新規/解除）→ 分析 `Card`。差分/分析の一覧は `DataTable` または既存のリンクリストを踏襲
- 機能（取り込み・差分・削除・分析）は**不変**。見た目のみ共通部品化

## アクセシビリティ要件（全画面共通・FR-012 / SC-004）

- ランドマーク: `header` / `nav[aria-label]` / `main` を各 1 つ。ページ見出しは `Heading level=1`（PageHeader）
- サイドバートグルは `aria-expanded`、現在メニューは `aria-current="page"`
- モバイル Sheet はフォーカストラップ・Esc クローズ・トリガー復帰（`@repo/ui` Sheet）
- ライト/ダーク両テーマでコントラスト 4.5:1 以上。axe 違反 0 件
