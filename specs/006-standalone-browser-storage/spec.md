# Feature Specification: 認証なし・ブラウザ保存で完結する構成

**Feature Branch**: `006-standalone-browser-storage`

**Created**: 2026-09-17

**Status**: Implemented

**Input**: User description: "DB のデプロイは行わず、認証なども行わない。Vercel にデプロイする前提で完全に Next.js だけで動くものにする。保存内容はローカルストレージに保存するように"

## 位置づけ

003〜005 の仕様（フォロワーインポートと差分・管理画面シェル・ID 一覧）で定義したドメイン機能を、サーバー側の DB・認証なしで提供するための **横断的な構成ルール** を定義する。本仕様は新しいドメイン機能を追加しない。003〜005 の記述と競合する箇所は本仕様が優先する。001（ユーザー認証）・002（Instagram 連携）は本アプリでは提供しない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ログインなしで即座に使い始める (Priority: P1)

利用者がサイトを開くと、アカウント登録・ログインを経ずにホーム（トップ `/`・ダッシュボード）へ到達し、フォロワーインポートの全機能を使える。ホームには、データがブラウザ内（localStorage）にのみ保存されサーバーへ送信されないこと、運営側による利用者データの収集・解析・トラッキングを行っていないこと、共用パソコン・共有ブラウザでは取り込みを行わないこと（データは手動で削除するまで残る）、別の端末・ブラウザに引き継がれず、サイトデータの消去で失われることの注意を表示する。

**Acceptance Scenarios**:

1. **Given** 初めてサイトを開いた利用者, **When** トップページの導線からダッシュボードへ移動する, **Then** ログイン画面を経由せずに管理画面シェルとウィジェットが表示される
2. **Given** 任意のユーザー, **When** `/login`・`/signup` など旧認証 URL にアクセスする, **Then** Not Found になる

---

### User Story 2 - データは自分のブラウザにだけ保存される (Priority: P1)

取り込んだフォロワー一覧は、利用者のブラウザ（localStorage）にのみ保存され、サーバーや他の端末・他のブラウザには一切送信・共有されない。

**Acceptance Scenarios**:

1. **Given** ブラウザ A で取り込みを行った, **When** 別のブラウザ（別プロファイル / 別端末）で `/imports` を開く, **Then** 「まだ取り込みがありません」と表示される（003〜005 の FR「本人のみ参照可」はこれで充足する）
2. **Given** エクスポート ZIP を取り込む, **When** ネットワークを観察する, **Then** ファイル内容を含むリクエストは発生しない
3. **Given** ダッシュボードを開く, **When** 画面を見る, **Then** データがこのブラウザにのみ保存され、サイトデータの消去で失われる旨の案内が表示される

---

### User Story 3 - 保存容量の上限に達しても壊れない (Priority: P2)

localStorage の上限（ブラウザにより 5MB 前後）に達した場合、取り込みは失敗として日本語で案内され、中途半端なデータは残らない。

**Acceptance Scenarios**:

1. **Given** 保存領域がほぼ満杯, **When** 取り込みを実行する, **Then** 「保存容量の上限に達した」旨と「不要な取り込みの削除」を促す案内が表示され、履歴には新しい取り込みが現れない
2. **Given** プライベートブラウズ等で localStorage が使えない, **When** 取り込みを実行する, **Then** 保存領域を利用できない旨の案内が表示される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは認証・認可を持たず、すべての画面に未ログインでアクセスできなければならない。001 の画面（ログイン・新規登録）と `proxy.ts` のリダイレクトは提供しない
- **FR-002**: 003〜005 で「本人のみ参照・更新できる」と定義されたデータは、利用者のブラウザの localStorage にのみ保存し、サーバーへ送信してはならない。キーはアプリ固有のプレフィックス（`yorunimahouwokakerarete:`）で名前空間を分ける
- **FR-003**: 003〜005 の Server Actions / Server Components によるデータ取得・更新は、Client Components からの読み書き（`features/<name>/client/`）+ TanStack Query に置き換え、戻り値の型（`ActionResult`）・エラーメッセージ・画面の状態分岐は維持しなければならない
- **FR-004**: 取り込みの保存は原子的でなければならない（003 FR-009 の維持）。複数キーへの書き込みは全件成功か全件取り消しとし、失敗時は保存前の状態に戻す
- **FR-005**: 一覧エントリは容量を節約する圧縮形式（`[username, followedAt(epoch 秒) | null, profileUrl?]`・正規 URL は省略）で保存し、読み出し時に 003 / 005 が期待する形へ復元しなければならない
- **FR-006**: 容量超過（QuotaExceededError）・保存領域の利用不可は日本語の案内に変換し、生のエラーを表示してはならない
- **FR-007〜FR-010**: 廃止（Instagram 連携機能の削除に伴い要件を撤回。番号は欠番として維持する）
- **FR-011**: 別タブでの保存変更（`storage` イベント）を検知した場合、表示中のクエリを無効化して最新状態へ追従しなければならない
- **FR-012**: 004 の管理画面シェルは維持するが、上部バーのユーザー表示・ログアウト導線は置かない。ダッシュボード（ホーム `/`）には保存先がブラウザである旨の案内と、取り込んだデータをすべて削除する操作（確認ステップ付き）を表示する
- **FR-013**: サーバー側に DB・秘密情報・永続ストレージ・Route Handler を必要とせず、Vercel の標準的な Next.js デプロイで動作しなければならない

### Key Entities（保存キー）

| localStorage キー（`yorunimahouwokakerarete:` 以降） | 内容 | 関連仕様 |
|---|---|---|
| `follower-imports` | 取り込みサマリの配列（id / accountUsername / followersCount / followingCount / importedAt）。保存時に最大 2 件（最新 + 前回）に収め、原則すべて同じ accountUsername を持つ（007） | 003 / 007 |
| `follower-import-entries:<importId>:<kind>` | 圧縮形式の一覧エントリ配列（username 昇順）。記録の取り除き時に同じ原子的書き込みで削除（007） | 003 / 005 / 007 |

## Success Criteria *(mandatory)*

- **SC-001**: 003〜005 の受け入れシナリオ（e2e）が、DB・ログインなしで全件通る（データ準備は localStorage 操作で行う）
- **SC-002**: 取り込み時にファイル内容を含む外部送信が 0 件である
- **SC-003**: フォロワー 1 万件規模の取り込みが 10 秒以内に差分表示まで完了し、保存サイズが 1 取り込みあたり 1MB 未満に収まる
- **SC-004**: 容量超過・保存不可の異常系で、日本語の案内が 100% 表示され、履歴に中途半端な取り込みが現れない
- **SC-005**: `next build` がサーバー側の環境変数・外部接続なしで成功する

## Assumptions

- Instagram API との連携（アカウント接続・フォロワー数の自動取得）は行わない。データの入口は Instagram のデータエクスポートの取り込み（003）のみとする
- localStorage の上限はブラウザ実装依存（多くは 5MB 前後）とし、アプリ側で厳密な残量管理は行わない。超過時は案内 + 履歴削除の導線で回復する
- 複数アカウント・複数端末間の同期・エクスポート（CSV 等）はスコープ外（003 / 005 の方針どおり）
- 対象ユーザーは日本語話者とし、画面文言は日本語で提供する
