# Feature Specification: アカウント ID による前回比較と保存件数の上限

**Feature Branch**: `007-account-scoped-comparison`

**Created**: 2026-09-18

**Status**: Implemented（2026-09-18）

**Input**: User description: "フォロワーの前保存した時の記録を比較できるようにしたい　データは前の読み込みと比較して　比較なので最大保存数は2件にする　インポート時のアカウントIDで比較対象を決める" + 追記 "ダッシュボードで簡単な比較が見られるようにしたい"

## 位置づけ

003（フォロワーリストのインポートと差分表示）が定義する「前回との差分」の **比較対象の決め方** と **記録の保持ルール** を見直す仕様。003 は「直前の取り込み」を比較対象にし、履歴を無制限に保持していたが、本仕様では次の 3 点に変更する。

1. 比較対象は **取り込み時に指定したアカウント ID が同じ前回の記録** とする。本アプリで比較できるアカウントは **1 つだけ** で、別のアカウント ID の記録が残っている状態では取り込みを行わない
2. 記録は比較に必要な **最大 2 件（最新 + 前回）** だけ保持し、それより古い記録は新しい取り込みの保存時に自動的に置き換える
3. ダッシュボードのインポートサマリで、直近の取り込みと前回記録との **簡単な比較（増減の要約）** を見られるようにする

003 の記述と競合する箇所（US3 の無制限履歴・FR-006・FR-010 の「警告 + 確認で続行」）は本仕様が優先する。保存先がブラウザであること（006）は変わらない。

## Clarifications

### Session 2026-09-18

- Q: 「最大保存数 2 件」はアカウント ID ごとの上限か、ブラウザ全体の上限か → A: ブラウザ全体で最大 2 件。本アプリで比較できるのは 1 アカウントのみで、置き換え対象は同じアカウント ID の記録に限る。別アカウントの記録が残っている状態では取り込みを拒否し、削除を促す
- Q: 上限超過時に最も古い記録を置き換える際、確認操作を挟むか → A: 確認なしで自動的に置き換える。取り込み画面に「最も古い記録が置き換わる」案内を常時表示する（確認ダイアログは出さない）
- Q: アカウント ID は利用者の入力か、エクスポートから自動取得するか → A: エクスポートに本人アカウント名が含まれていればそれを入力欄の既定値として自動入力し、利用者が確認・修正して取り込む。取れない場合は保存済み記録のアカウント ID を既定値にし、それも無ければ手入力を必須にする（本人アカウント名はフォロワー / フォロー中ファイルだけの取り込みや HTML 形式では取れないため、自動取得だけには頼らない）
- Q: 本機能の適用前から保存されていた記録（3 件以上・別アカウント混在）はいつ整理するか → A: 次の取り込み時に整理する。同じアカウント ID の 3 件目以降は上限処理で自動削除し、別アカウントの記録が残っていれば取り込みを拒否して削除を案内する。画面を開いただけでは削除しない
- Q: 別アカウントの記録があって拒否されたとき、その場で削除して取り込める導線を用意するか → A: 用意する。拒否メッセージに「既存の記録をすべて削除して取り込む」操作を付け、確認ダイアログで承諾すると既存記録の削除と新しい取り込みの保存をまとめて原子的に行う

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同じアカウントの前回記録と比較する (Priority: P1)

利用者がアカウント ID を指定してエクスポートを取り込むと、**同じアカウント ID で保存されている前回の記録** と比較され、「新しくフォローしてくれた相手」「フォローを外した相手」の件数と一覧が表示される。本アプリが保持する記録は 1 つのアカウント ID のものに限られるため、別のアカウント ID の記録が残っている状態で取り込もうとすると、取り込みは行われず、その場で「既存の記録をすべて削除して取り込む」か（確認付き）、取り込みをやめるかを選べる。

**Why this priority**: 「前回保存した時の記録と比較する」が本機能の中核価値。比較対象を誤る（別アカウントの記録と比べる）と差分そのものが意味を持たなくなる。

**Independent Test**: アカウント A で 2 回取り込んで差分が A の 1 回目と比較されること、その状態でアカウント B を指定すると取り込みが拒否されること、拒否メッセージの「既存の記録をすべて削除して取り込む」を確認付きで実行すると A の記録が消えて B が保存されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** アカウント A の記録が 1 件保存されている, **When** アカウント A を指定して新しいエクスポートを取り込む, **Then** A の前回記録と比較した「新規フォロワー」「フォロー解除した相手」の件数と一覧が表示される
2. **Given** アカウント A の記録が保存されている（1 件以上）, **When** アカウント B を指定してエクスポートを取り込む, **Then** 取り込みは行われず「このアプリで比較できるアカウントは 1 つで、別アカウントの記録が保存されている」旨の案内と、「既存の記録をすべて削除して取り込む」操作が表示される。A の記録は変化しない
3. **Given** シナリオ 2 の拒否が表示されている, **When** 「既存の記録をすべて削除して取り込む」を選び、確認ダイアログで承諾する, **Then** A の記録（一覧を含む）がすべて削除され、B の記録が保存されて「比較対象がまだない」旨と次回同じアカウント ID で取り込むと比較できる案内が表示される。確認を取り消した場合は何も変化しない
4. **Given** シナリオ 3 の削除 + 保存の途中で失敗した（容量超過など）, **When** 結果を見る, **Then** A の記録は削除されず B の記録も現れず、日本語の失敗理由が表示される
5. **Given** アカウント ID を大文字・小文字や前後の空白だけ違えて入力した, **When** 取り込む, **Then** 同じアカウント ID として扱われ、前回記録と比較される（別アカウントとして拒否されない）
6. **Given** 前回と同一内容のエクスポートを同じアカウント ID で取り込んだ, **When** 差分を表示する, **Then** 「変化なし（差分 0 件）」であることが明示される

---

### User Story 2 - 記録は最新と前回の 2 件だけ残る (Priority: P1)

同じアカウント ID で 3 回目の取り込みを行うと、最も古い記録が自動的に取り除かれ、保存されている記録は常に「最新」と「前回」の 2 件に収まる。取り込み前に、古い記録が置き換わることが画面上で分かる。

**Why this priority**: ブラウザ保存の容量は限られており（006）、比較に必要なのは直近 2 件だけ。無制限に溜めると容量超過で取り込み自体が失敗する。US1 と同時に成立させることで、利用者が履歴の整理を意識せずに継続利用できる。

**Independent Test**: 同じアカウント ID で 3 回取り込み、履歴に記録が 2 件（2 回目と 3 回目）だけ残り、3 回目の差分が 2 回目と比較されていることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** アカウント A の記録が 2 件保存されている, **When** アカウント A で 3 回目の取り込みを行う, **Then** 保存されている記録は 2 回目と 3 回目の 2 件になり、1 回目の記録（一覧を含む）は取り除かれる
2. **Given** アカウント A の記録が 2 件保存されている, **When** 取り込み画面でアカウント A を指定する, **Then** 取り込みを実行すると最も古い記録が置き換わる旨の案内が表示される
3. **Given** アカウント A の記録が 2 件保存されている, **When** アカウント B を指定して取り込む, **Then** 置き換えは行われず US1 シナリオ 2 の拒否と案内になる（別アカウントの記録を上限処理で消してしまわない）
4. **Given** アカウント A で 3 回目の取り込みを実行した, **When** 保存の途中で失敗する（容量超過など）, **Then** 1 回目の記録は取り除かれず、3 回目の記録も現れず、失敗前の状態がそのまま残る

---

### User Story 3 - 履歴を見て整理する (Priority: P2)

利用者は取り込み履歴で、保存されている記録（最大 2 件）と、それがどのアカウント ID のものかを確認でき、記録を選ぶとその記録の差分（同じアカウント ID の前回記録との比較）を再表示できる。不要な記録は削除でき、削除後も残った記録同士で比較が整合する。別のアカウントに切り替えたい場合は、ここから既存の記録を削除する。

**Why this priority**: 履歴はアカウントの切り替え（既存記録の削除）の入口でもあるため、どのアカウントの記録が残っているかが分からないと US1 シナリオ 2 の案内に従えない。ただし比較（US1）と保持ルール（US2）が成立していれば初期価値は出る。

**Independent Test**: 記録が 2 件ある状態で履歴を開き、各行にアカウント ID が表示されること、最新記録を削除すると残った記録が「比較対象なし」になること、2 件とも削除すると別アカウントで取り込めることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 記録が保存されている, **When** 履歴を開く, **Then** 各記録の取込日時・フォロワー件数に加えてアカウント ID が表示され、新しい順に並ぶ
2. **Given** アカウント A の記録が 2 件保存されている, **When** 古い方（前回）の記録を選ぶ, **Then** その記録は「比較対象がまだない」として表示される（さらに前の記録は保持していないため）
3. **Given** アカウント A の記録が 2 件保存されている, **When** 最新記録を削除（確認ステップ付き）する, **Then** 残った記録が最新となり、その差分は「比較対象がまだない」と表示される
4. **Given** アカウント A の記録が 2 件保存されている, **When** 前回記録を削除する, **Then** 最新記録の差分は「比較対象がまだない」と表示され、次回 A で取り込むとその最新記録と比較される
5. **Given** 別アカウントの取り込みが拒否された（US1 シナリオ 2）, **When** その場の操作を使わず履歴から記録を 1 件ずつすべて削除する, **Then** 履歴は空になり、別アカウント ID での通常の取り込みが可能になる（履歴からの削除も引き続き切り替え手段として使える）

---

### User Story 4 - ダッシュボードで簡単な比較を見る (Priority: P2)

利用者がホーム（ダッシュボード）を開くと、インポートサマリに直近の取り込みのアカウント ID・フォロワー件数に加えて、**前回記録との比較の要約**（フォロワー件数の増減・新規フォロワー件数・フォロー解除件数）が表示される。詳しい一覧は取り込み詳細へ移動して確認する。

**Why this priority**: 「前回からどれだけ変わったか」を毎回インポート画面まで移動せずに一目で把握できることが、比較機能の日常的な使いやすさを決める。ただし比較そのもの（US1）が成立していれば価値は出るため P2。

**Independent Test**: 同じアカウント ID で内容の異なる 2 回の取り込みを行った状態でダッシュボードを開き、フォロワー件数の増減（±N）と新規・解除の件数が差分画面と一致して表示されることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 同じアカウント ID の記録が 2 件保存されている, **When** ダッシュボードを開く, **Then** 直近の取り込みのアカウント ID・フォロワー件数と、前回比のフォロワー増減（±N）・新規フォロワー件数・フォロー解除件数が表示される
2. **Given** 比較の要約が表示されている, **When** 要約から詳細への導線を選ぶ, **Then** 直近の取り込みの差分画面（一覧付き）へ移動する
3. **Given** 記録が 1 件だけ保存されている, **When** ダッシュボードを開く, **Then** フォロワー件数は表示され、比較部分は「比較対象がまだない」旨と次回取り込みの案内になる
4. **Given** 前回と同一内容の取り込みが直近, **When** ダッシュボードを開く, **Then** 増減 0・新規 0 件・解除 0 件として「変化なし」が明示される
5. **Given** 記録が 1 件もない, **When** ダッシュボードを開く, **Then** 従来どおり「まだ取り込みがありません」と取り込みへの導線が表示される

---

### Edge Cases

- **本機能の適用前に 3 件以上の記録が保存されていた場合**: 画面を開いただけでは記録を消さない。次に取り込みを保存する時点で、上限（2 件）に収まるよう古い記録から取り除く（例: 同じアカウントの記録が 4 件ある状態で取り込むと、古い 3 件が取り除かれ、新しい記録 + 直前の 1 件が残る）
- **本機能の適用前に複数のアカウント ID の記録が混在して保存されていた場合**: 画面を開いただけでは消さない。取り込み時は US1 シナリオ 2 と同じく、指定したアカウント ID と異なる記録が残っていれば拒否して削除を案内する
- **取り込み時に指定したアカウント ID が、エクスポートに含まれる本人アカウント名と一致しない場合**: 入力ミスの可能性があるため警告し、利用者が明示的に確認した場合のみ続行する（指定したアカウント ID の記録として保存される）
- **アカウント ID の既定値**: 選択したエクスポートに本人アカウント名が含まれていれば、それを入力欄に自動入力する（利用者は修正できる）。含まれていなければ保存されている記録のアカウント ID を既定値にし、記録が 1 件もなければ入力を必須にする
- **自動入力された本人アカウント名が、保存済み記録のアカウント ID と異なる場合**: 別アカウントのエクスポートを選んだ可能性が高いため、そのまま取り込むと FR-007 により拒否される。取り込み前の段階で「保存済みの記録は別アカウントのもの」である旨を案内し、利用者が気付けるようにする
- **利用者が自動入力された値を書き換えた場合**: 書き換え後の値が本人アカウント名と一致しなければ、入力ミスの可能性として警告し、明示的な確認を経た場合のみ続行する（FR-008）
- **保存されている記録と同一日時の取り込み**（同一秒内の連続取り込みなど）: 新しい方を最新として扱い、前回との順序が入れ替わらない
- **比較対象となる前回記録の一覧が破損・欠落している場合**: 差分は「比較対象がまだない」として扱い、生のエラーは表示しない（ダッシュボードの要約も同じ扱い）
- **ダッシュボードの比較要約の読み込みに失敗した場合**: フォロワー件数などの表示できる部分は表示し、比較部分だけ取得失敗の案内に置き換える（生のエラーは表示しない）
- **フォロワー 0 件のエクスポート**: 従来どおり正常に取り込め、前回記録との比較で全件が「フォロー解除」として表示される
- **相手のユーザーネーム変更**: 003 と同じく「解除 + 新規」として二重計上され得る制約を差分画面に注記する（変更なし）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは取り込みごとに、利用者が取り込み時に指定した **アカウント ID** を記録と一緒に保存しなければならない。アカウント ID は前後の空白を除き大文字・小文字を区別せずに同一性を判定する
- **FR-002**: 取り込み完了時および記録を選択した時の差分は、**同じアカウント ID を持つ記録のうち、その記録より前に取り込まれた最新のもの** を比較対象として計算しなければならない。別のアカウント ID の記録を比較対象にしてはならない（003 FR-004 の比較対象を置き換える）
- **FR-003**: 比較対象が存在しない場合、差分画面は「比較対象がまだない」旨と「次回同じアカウント ID で取り込むと比較できる」案内を表示しなければならない
- **FR-004**: システムは **ブラウザ全体で最大 2 件** の記録（最新 + 前回）だけを保持しなければならない。新しい取り込みを保存する際、記録が上限を超える場合は、**同じアカウント ID の** 古い記録から順に、その記録に属する一覧も含めて取り除く（003 FR-006 の無制限履歴を置き換える）
- **FR-005**: 上限による古い記録の取り除きは、新しい記録の保存と **一体の原子的な操作** でなければならない。保存が途中で失敗した場合、古い記録は取り除かれず新しい記録も現れない（003 FR-009 / 006 FR-004 の維持）
- **FR-006**: 取り込み画面は、保存済みの記録がすでに上限件数に達している場合、取り込みを実行すると最も古い記録が置き換わる旨を **取り込み前に** 表示しなければならない。この表示は確認操作を要求しない（案内のみ）
- **FR-007**: 取り込み時に指定したアカウント ID と **異なるアカウント ID の記録が 1 件でも保存されている場合**、システムは取り込みを行わず、「このアプリで比較できるアカウントは 1 つである」旨の案内を表示しなければならない。上限処理（FR-004）で別アカウントの記録を取り除いてはならない（003 FR-010 の「警告 + 確認で続行」を置き換える）
- **FR-007a**: FR-007 の案内には「既存の記録をすべて削除して取り込む」操作を伴わせなければならない。この操作は確認ダイアログ（破壊的操作として明示）で承諾された場合のみ実行され、既存記録（一覧を含む）の全削除と新しい取り込みの保存を **一体の原子的な操作** で行う。途中で失敗した場合は既存記録が残り、新しい記録は現れない（FR-005 と同じ保証）。確認を取り消した場合は何も変更しない
- **FR-008**: 取り込み時に指定したアカウント ID が、エクスポートに含まれる本人のアカウント名と一致しない場合、システムは警告し、利用者の明示的な確認を経ない限り取り込まない（入力ミス検出。003 FR-010 のうちこの部分は維持）
- **FR-009**: 取り込み履歴は、各記録のアカウント ID・取込日時・フォロワー件数・フォロー中件数を新しい順に一覧表示しなければならない
- **FR-010**: 履歴からの記録の削除（確認ステップ付き・1 件ずつ）は引き続き提供し、削除後は残った記録同士で比較対象が再決定されなければならない（003 FR-007 の維持・比較対象の決め方だけ FR-002 に従う）。記録をすべて削除すると、FR-007a を使わなくても別のアカウント ID で取り込めるようになる
- **FR-011**: 本機能の適用前から上限を超えて保存されていた記録、または複数のアカウント ID が混在して保存されていた記録は、画面表示だけでは取り除かず、次の取り込み時に FR-004 / FR-007 のルールに従って扱わなければならない。すなわち、取り込むアカウント ID と同じ記録が 3 件以上あれば上限処理で古い順に自動削除し（残るのは新しい記録と合わせて 2 件）、異なるアカウント ID の記録が 1 件でもあれば取り込みを拒否して削除を案内する。それまでの間、履歴は保存されている記録をすべて表示する
- **FR-012**: アカウント ID の入力欄の既定値は次の優先順で決めなければならない。(1) 選択したエクスポートから取り出せた本人アカウント名（ファイル選択の時点で自動入力し、利用者が修正できる）、(2) 保存されている記録のアカウント ID、(3) いずれも無い場合は既定値なしで入力を必須とする。取り込みに使うアカウント ID は、既定値の出どころにかかわらず、取り込み実行時に入力欄にある値とする
- **FR-013**: 比較対象・保持件数・置き換え案内・別アカウント拒否の案内・ダッシュボードの比較要約に関する画面文言はすべて日本語で提供し、生のエラー情報を表示してはならない（003 FR-008 / 006 FR-006 の維持）
- **FR-014**: 履歴のアカウント ID 表示・置き換え案内・別アカウント拒否の案内・比較対象なしの案内・ダッシュボードの比較要約は、キーボードのみで到達でき、支援技術に伝わる形で提供しなければならない（WCAG 2.1 AA・003 FR-013 の維持）
- **FR-015**: ダッシュボードのインポートサマリは、直近に取り込んだ記録について、アカウント ID・フォロワー件数と、FR-002 で決まる比較対象との **比較の要約**（フォロワー件数の前回比増減・新規フォロワー件数・フォロー解除件数）を表示しなければならない。比較対象がない場合は「比較対象がまだない」旨と次回取り込みの案内を表示し、差分 0 件の場合は「変化なし」を明示する
- **FR-016**: ダッシュボードの比較要約から、その記録の差分画面（一覧付き）へ移動できなければならない。要約に相手の一覧そのものは含めない（一覧は差分画面の役割）
- **FR-017**: ダッシュボードの比較要約に表示する各件数は、同じ記録の差分画面が表示する件数と一致しなければならない

### Key Entities

- **アカウント ID**: 取り込み時に利用者が指定する対象 Instagram アカウントの識別名。前後の空白を除き小文字に正規化して同一性を判定する。保存されている記録はすべて同じアカウント ID を持ち（1 アカウントのみ）、比較対象の決定はこの単位で働く
- **フォロワーインポート（取り込み記録）**: 1 回の取り込みに対応する記録（003 と同じ）。アカウント ID・取込日時・フォロワー件数・フォロー中件数を持つ。**ブラウザ全体で最大 2 件（最新 + 前回）** まで保持される
- **フォロワーリストエントリ**: 記録に含まれる相手 1 人分（003 と同じ）。記録が取り除かれると一緒に取り除かれる
- **差分結果**: ある記録と、**同じアカウント ID を持つ直前の記録** との比較から導出される「新規フォロワー」「フォロー解除した相手」の集合。保存せず都度計算する導出データ（003 と同じ。比較対象の決め方のみ変更）
- **比較要約**: 差分結果から導出される件数だけの要約（フォロワー件数の前回比増減・新規フォロワー件数・フォロー解除件数・比較対象の有無）。ダッシュボードで表示する。保存せず都度計算する導出データ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: アカウント A の記録が保存された状態でアカウント B の取り込みを試みるテストで、取り込みが 100% 拒否され、A の記録が変化する事例が 0 件である。「既存の記録をすべて削除して取り込む」を承諾した場合のみ A が消えて B が保存され、承諾なしで A が消える事例が 0 件である
- **SC-001a**: 別アカウントへの切り替え（拒否 → 全削除して取り込む → 差分画面到達）が、取り込み画面から離れずに完了できる
- **SC-002**: 同じアカウント ID で何回取り込んでも、保存記録が 3 件以上になることが 0 件である（取り込み直後の履歴で確認）
- **SC-003**: 上限による置き換えを含む取り込みで保存が途中失敗した場合、失敗前と保存内容が 100% 一致する（古い記録の消失・新しい記録の残留が 0 件）
- **SC-004**: 利用者が同じアカウント ID で 2 回目の取り込みを完了してから差分が表示されるまで、追加の操作（比較対象の選択など）を 0 回で到達できる
- **SC-005**: 3 回目の取り込みで、取り込み前の画面に置き換えの案内が 100% 表示される
- **SC-006**: 003 / 005 の既存受け入れシナリオ（取り込み・差分・一覧・削除）が、比較対象の決め方と保持ルールの変更後も全件通る（無制限履歴・別アカウントの確認続行に依存するシナリオは本仕様に合わせて改める）
- **SC-007**: インポート関連の全画面とダッシュボードが自動アクセシビリティ検査（WCAG 2.1 AA 相当）で違反 0 件である（003 SC-006 の維持）
- **SC-008**: 同じアカウント ID で 2 回目の取り込みを終えた利用者が、ダッシュボードを開くだけで（追加の操作 0 回で）前回比の増減・新規・解除の件数を確認できる
- **SC-009**: ダッシュボードの比較要約の各件数が、同じ記録の差分画面の件数と 100% 一致する（不一致 0 件）

## Assumptions

- 本アプリで比較できるアカウントは **1 つだけ** とし、保存される記録はすべて同じアカウント ID を持つ（Clarifications 参照）。別アカウントへの切り替えは既存記録の全削除（拒否メッセージからの一括操作、または履歴からの個別削除）で行い、複数アカウントの同時管理はスコープ外
- 「アカウント ID」は 003 で利用者が入力していた「対象アカウント名（ユーザーネーム）」と同じもの。エクスポートに本人のアカウント名が含まれる場合は入力欄の既定値（FR-012）と入力ミス検出（FR-008）に使うが、識別のキーはあくまで取り込み実行時に入力欄にある値とする（Clarifications 参照）
- 本人アカウント名は、エクスポート ZIP に本人情報ファイルが含まれる場合にのみ取り出せる。フォロワー / フォロー中ファイルだけを選んだ取り込みや HTML 形式のエクスポートでは取り出せないため、自動入力は補助であり、手入力の経路は常に残す
- 上限を超えた古い記録は **確認なしで自動的に置き換える**（取り込み前の案内のみ・Clarifications 参照）。比較に必要なのは直近 2 件であり、毎回確認を求めると継続利用の手間が増えるため。残したい記録がある場合の保全（エクスポート等）はスコープ外
- 比較は **隣接する 2 件**（最新と前回）に限る。任意の 2 時点比較・3 件以上の推移表示はスコープ外（保持件数の上限と両立しないため）
- 履歴からの削除は記録単位で引き続き提供する。一括削除は別アカウント切り替え時の「すべて削除して取り込む」（FR-007a）に限り、履歴画面での一括削除・アカウント ID の変更（記録の付け替え）はスコープ外
- 「簡単な比較」は **件数の要約**（前回比の増減・新規件数・解除件数）と解釈し、相手の一覧はダッシュボードに出さない。一覧は差分画面の役割とし、ダッシュボードはそこへの導線を持つ
- 保存先はブラウザ（006）のまま変更しない。保存容量の異常系の扱い（日本語案内・原子性）も 006 に従う
- 対象ユーザーは日本語話者とし、画面文言は日本語で提供する
