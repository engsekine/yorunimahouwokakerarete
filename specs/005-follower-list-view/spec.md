# Feature Specification: フォロワー・フォロー中の ID 一覧表示

**Feature Branch**: `005-follower-list-view`

**Created**: 2026-07-17

**Status**: Draft

**Input**: User description: "フォロワー　フォロー中の　id を一覧で表示できるようにしたい"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - フォロワーの ID 一覧を見る (Priority: P1)

取り込み済みのユーザーが、ある取り込みに含まれる**フォロワー全員のユーザー ID（ユーザーネーム）を一覧**で確認できる。差分（増減）ではなく、その時点の全メンバーがそのまま並ぶ。各 ID から Instagram のプロフィールへ移動できる。

**Why this priority**: 「いま誰がフォロワーなのか」を一望する最も基本的な確認手段。003 は差分・非相互分析を出すが、全員のフラットな一覧は未提供のため、本機能の中核。

**Independent Test**: フォロワーを含む取り込みを開き、フォロワー ID が全件（件数どおり）並び、各 ID からプロフィールへ移動できることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** フォロワーを含む取り込みがあるユーザー, **When** その取り込みの一覧を開く, **Then** フォロワーのユーザー ID が件数とともに全件表示される
2. **Given** フォロワー一覧が表示されている, **When** 一覧内の ID を選ぶ, **Then** その相手の Instagram プロフィール（外部）を開ける
3. **Given** フォロワー 0 件の取り込み, **When** 一覧を開く, **Then** 「フォロワーがいません」と明示される

---

### User Story 2 - フォロー中の ID 一覧を見る (Priority: P1)

同じ取り込みについて、**フォロー中（自分がフォローしている相手）のユーザー ID 一覧**も確認できる。フォロワー一覧とフォロー中一覧は切り替え（タブ等）で見分けられ、それぞれ件数が分かる。

**Why this priority**: フォロワーと対になる基本情報。フォロー中一覧がエクスポートに含まれる場合に、全員を一望できる。

**Independent Test**: フォロー中を含む取り込みで、フォロー中 ID が全件表示され、フォロワー一覧と切り替えられることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** フォロー中を含む取り込み, **When** フォロー中の一覧に切り替える, **Then** フォロー中のユーザー ID が件数とともに全件表示される
2. **Given** フォロワー一覧を見ている, **When** フォロー中に切り替える, **Then** 表示が切り替わり、現在どちらを見ているかが分かる
3. **Given** フォロー中一覧を含まない取り込み（フォロワーのみ）, **When** フォロー中の一覧を開く, **Then** フォロー中一覧が含まれていない旨が案内される

---

### User Story 3 - 一覧から目的の ID を探す (Priority: P2)

一覧が多数（数千〜1 万件）でも、ユーザー ID の一部を入力して**絞り込み検索**でき、目的の相手を素早く見つけられる。

**Why this priority**: 大規模アカウントでは全件スクロールは非現実的。ただし基本の一覧表示（US1/US2）が先。

**Independent Test**: 多数のフォロワーを含む取り込みで、ID の一部を入力すると該当する ID だけに絞り込まれることを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 多数のフォロワーがいる一覧, **When** ID の一部を入力する, **Then** その文字列を含む ID だけが表示され件数が更新される
2. **Given** 検索語に一致する ID がない, **When** 検索する, **Then** 「該当なし」と明示される
3. **Given** 検索語を消す, **When** 入力を空にする, **Then** 全件表示に戻る

---

### Edge Cases

- フォロワーが非常に多い（1 万件規模）一覧でも、表示・スクロール・検索が破綻しない
- 同じ相手が複数回現れない（取り込み時に重複排除済みの前提を一覧でも保つ）
- ユーザー ID に使える文字（英数字・ピリオド・アンダースコア）以外が含まれても表示が崩れない
- フォロワー・フォロー中の両方が 0 件（空のエクスポート）でも一覧画面自体は正常に開ける
- 本人以外の取り込みの一覧は閲覧できない（アクセス制御）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは取り込み単位で、フォロワーのユーザー ID 全件を一覧表示できなければならない（差分ではなく全メンバー）
- **FR-002**: システムは同一取り込みのフォロー中のユーザー ID 全件を一覧表示でき、フォロワー一覧と切り替えられなければならない
- **FR-003**: 各一覧はその種別の件数を表示しなければならない
- **FR-004**: 一覧の各 ID から、その相手の Instagram プロフィール（外部）へ移動できなければならない
- **FR-005**: 一覧が空（0 件）の場合、および対象種別のデータが取り込みに含まれない場合は、それぞれ区別できる案内を表示しなければならない
- **FR-006**: 一覧はユーザー ID の部分一致で絞り込み検索でき、絞り込み結果の件数が分かるようにしなければならない
- **FR-007**: 一覧の表示・検索は 1 万件規模でも実用的な速度で動作しなければならない
- **FR-008**: 取り込みデータの一覧は本人のみが閲覧でき、他ユーザーからは一切アクセスできないようにしなければならない
- **FR-009**: 一覧・切り替え・検索の各 UI はキーボードのみで操作でき、件数や絞り込み結果の変化が支援技術に伝わる（WCAG 2.1 AA 準拠）ようにしなければならない

### Key Entities

- **リストエントリ（既存）**: 取り込みに含まれる相手 1 人分の記録（種別＝フォロワー/フォロー中・ユーザー ID＝ユーザーネーム・プロフィール URL）。本機能はこの既存データを全件表示・検索する読み取り専用機能で、新しいデータは追加しない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは取り込みを開いてから 2 アクション以内でフォロワー ID 一覧・フォロー中 ID 一覧のいずれにも到達できる
- **SC-002**: 一覧に表示される ID の件数が、その取り込みの当該種別の保存件数と 100% 一致する（欠落・重複 0 件）
- **SC-003**: フォロワー 1 万件規模でも、一覧表示および検索結果の反映が実用的（体感 1 秒以内）に完了する
- **SC-004**: 他ユーザーの一覧へのアクセスが 0 件である（本人以外の参照経路が存在しない）
- **SC-005**: 一覧関連の画面が自動アクセシビリティ検査（WCAG 2.1 AA 相当）で違反 0 件である

## Assumptions

- 一覧の元データは **003（フォロワーインポート）で取り込んだリストエントリ**とする
- 「ID」は Instagram の**ユーザーネーム（ハンドル）**を指す（エクスポートに安定した数値 ID は含まれないため。003 の前提を踏襲）
- 本機能は既存の取り込みデータに対する**読み取り専用の表示・検索**であり、新しいデータの保存・DB スキーマ追加は行わない
- 一覧の対象は特定の 1 取り込み（最新または履歴から選んだもの）とする。複数取り込みを横断した統合一覧はスコープ外
- 一覧の並び順はユーザー ID の昇順を既定とする（安定した順序で探しやすくするため）
- 検索は大文字小文字を区別しない部分一致とする
- 表示・エクスポート等の二次利用（CSV 出力等）はスコープ外（003 の方針どおり本人閲覧のみ）
- 対象ユーザーは日本語話者とし、画面文言は日本語で提供する
